# Paseo workspace labels

Give reusable checkouts names that show the work happening in them.

```text
alpha  →  Improve search · alpha
beta   →  Fix export timeout · beta
```

This Paseo plugin follows existing conversation titles or Git branch names. It
runs in the background without model calls or messages to your coding agents.

## Install

Requires Paseo 0.11.1. Enable plugins in Paseo Settings, then install:

```sh
paseo plugin install git:dwaxe/paseo-workspace-labels --ref v0.1.3
```

Open **Workspace names** in the sidebar or run **Configure this workspace name**
from the Command Center. Choose a checkout label, such as `alpha`, and enable
automatic naming for that workspace. Every workspace starts with naming off.

## Naming

- **Conversation title** follows the newest eligible conversation created in the
  workspace. You can pin a particular conversation instead. Child, archived,
  closed, and internal conversations are excluded. An empty or placeholder title
  leaves the current workspace name alone until a meaningful title appears.
- **Git branch** formats the current branch name into words. Git must be installed
  on the daemon host. A detached checkout keeps its current workspace name.
- Both modes append your checkout label. A manual workspace rename pauses the
  plugin for that workspace. **Resume automatic naming** explicitly restarts it.

Conversation metadata changes trigger updates. A one-minute background check
catches branch changes and missed events. After a plugin or daemon restart,
monitoring begins when you open Workspace names or a workspace/conversation
lifecycle event occurs.

The plugin uses existing names as input. A topic change that does not change the
conversation title or branch will not produce a new workspace name. Existing
conversation titles may have been generated by Paseo's own metadata naming.

## Data and permissions

The plugin reads workspace and conversation metadata, plus Git branch names in
branch mode. It writes workspace titles, host settings, and private recovery
state. It does not read conversation bodies or send data to external services.
Paseo plugins run with the daemon user's permissions.

Settings use Paseo's host settings store. Recovery state is under
`$XDG_STATE_HOME/paseo-workspace-labels/` (default `~/.local/state/`), separated by
`PASEO_HOME`. For multiple daemons launched with different `--home` flags, set a
distinct absolute `PASEO_WORKSPACE_LABELS_STATE_DIR` in each daemon's environment.

Names are checked immediately before each update and uncertain writes are
reconciled on the next check. Paseo currently has no atomic compare-and-set title
operation, so a manual rename in the final read/write interval can still race.

## Development

```sh
npm ci --ignore-scripts
npm run check
```

Use Node.js 22 or later. The tests use isolated state files and fake daemon APIs.
The SDK, React, React Native, TanStack Query, and Zod are development dependencies;
Paseo supplies them at runtime. `.npmrc` disables npm's automatic peer installation
because the host supplies the complete SDK peer set.
